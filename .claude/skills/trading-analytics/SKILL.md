## Ground-truth data (the heart of everything)
Newest match wins (ledger: newest mtime; holdings: date in the file name, then mtime), so the user just drops fresh exports there:
- `transactions-and-notes-export*.csv` — full ledger (UTF-16, tab separated, Swedish headers).

## Domain rules learned the hard way
- The type string for sells is **`SÅLT`** (Å, not Ä); buys `KÖPT`. Use the `\u` escapes in `trade_analytics.py`.
- `Total Avgift` = all fees (SEK); `Courtage` = commission; FX/other = difference. `Belopp` is net of fees (buy negative).
- Ledger rebuild must equal holdings export; warnings list any mismatch (currently only a 0-value "Lunar Royalties Corp SDB TAX" row).
- Corporate actions: BYTE/SPLIT pairs share a verification number -> ISIN alias + cost carried; FISSION / dividend-in-kind get zero cost (so later sells of those look like pure gain).
- Realised P&L = average cost in SEK incl. fees (differs a little from Nordnet's `Resultat`); holding period = FIFO.
- Compare prices across listings in SEK (`price * fx`), never raw (AstraZeneca trades in both USD and SEK).
- Asset type/country are heuristics (name regex, ISIN prefix); the CSV has no sector data — never invent one.
- Windows 1W/1M count back from today's date, not from the last CSV date.

## Advice engine (replaces "Tomorrow's Signals")
`advisor.py` -> `/api/advice` (cached per payload + profile for 10 min (`CACHE_SECONDS`; Portfolio page re-asks every 10 min, Analytics on every 10 s poll); Yahoo 2y adjusted closes in `history_cache.json`, gitignored, 6 h TTL). Position management, NOT a forecast. A back-test on the 77 held assets (5y daily, ~70k samples; scripts were in the session scratchpad, numbers are shown in the Advice tab) found: the old 8-indicator next-day score had no edge (Strong Buy: -0.25% next day, 43% up; rank IC ~ -0.02..-0.05), "trim when overbought" would have sold winners (+15% vs +9.6% next 63d), broken-trend has no sell edge, pullback-in-uptrend add is only a small tilt (+12.8% vs +10.5%). Caveats: survivorship (stocks you chose) and a 2021-26 bull market. So actions: TRIM = weight > 4% or theme (Yahoo sector) > 40% and weight >= 2.5% (give back a fifth); ADD = weight < 1.5%, close > 200d and 50d > 200d, 12-1 momentum > 0, 5-25% below 52w high, RSI < 68, theme not over cap (fill to 2%, min order 1 500 kr, score = momentum rank + pullback + low vol); BUYBACK = the same trend / pullback test on CLOSED positions (>= 7 days after the last sell, sector not over cap, 1.5% sized, shows sold price vs now when currencies match; history + sector lookups for ~110 closed assets make the first call slow, so a partial answer is cached only 90 s); CONSOLIDATE = < 1 500 kr; REVIEW = downtrend + negative momentum + > 15% under cost. Cards: fragmentation, theme concentration, portfolio vol / 1y max drawdown / avg correlation of top 30 (effective bets), trend health, size of changes. Constants at the top of advisor.py. Entry rules for ADD and BUYBACK come from `PROFILES` (conservative / balanced = default / aggressive: pullback range, max RSI, allowed trends, price above 50-day, days after a sell); `/api/advice?profile=`, chosen with the chips in the Advice tab and kept in localStorage `tv_advice_profile` (also used by the Assets column and the Portfolio ideas). The thresholds are my own choices (trend filter and 12-1 momentum are standard, the 5-25% pullback window is not) and were tuned on the same data as the back-test, so treat the edge as small. Failed history fetches are not retried for an hour (`_fail`). UI: Analytics tab "Advice", column "Add / trim" in the Assets table (sortable, tooltip = reasons), Portfolio page "Add / Trim Ideas" panel (`loadPredictions()` in app.js now calls /api/advice; the old client-side scoring was deleted). Assets table layout: Type and Ccy are one column, Last buy / Last sell columns were removed, and below 1360 px the Bought / Sold columns hide (CSS nth-child 7 and 8 of `#asset-table`; keep them at those positions if columns change); it fits at 1100-1440 px with 13 px text. ## Volatility column, RSI rules, HTTPS
- **Vol 3M** (Portfolio tables): `volatility.py` = sample standard deviation of the last 63 daily close-to-close changes (>= 40 needed), in %, plus yearly (x sqrt(252)) and average absolute move. Data: the shared advisor history (`advisor._load()` / `_histories`, 2 years adjusted closes; funds use the Yahoo `0P...` NAV series, fine for volatility although never used for valuation). `for_assets()` never touches the network: missing / >12 h old series are fetched on a daemon thread. It travels in `/api/snapshot` as `assets[isin].vol_3m` ({daily, annual, avg_abs, days}) so the page does no maths; `app.js` `volCell()`; colour gold >= 3%, red >= 5%; column 11 is hidden below 700 px in responsive.css (7D sparkline code is gone).
- **RSI rules** (advisor.py `PROFILES`): philosophy = buy pullbacks in uptrends, take profit when stretched. ADD / BUYBACK need RSI(14) < `rsi_buy` AND trend in the profile's allowed states (Balanced: price above the 200-day with 50 > 200) AND 5-25% below the 52-week high; take-profit = TRIM of 1/3 of a holding in profit when RSI > `rsi_sell` (rule 3b in `advise()`). Profiles differ by 5 points: conservative 30/80 (also needs positive 12-1 momentum, 10-25% below the high, 14 days after a sell), balanced 35/75, aggressive 40/70 (mixed trend ok, up to 40% below the high, 3 days). Evidence (pooled 173 stocks, 2 years, bull market, overlapping windows; treat as indicative): next 21 days after RSI < 35 any trend +1.6% vs +3.0% for all days; RSI < 35 above the 200-day +3.6% (win 59%); RSI < 35 below it +1.2%; RSI < 30 +0.6%; RSI < 40 above the 200-day +3.55% (63 d +8.2%, baseline +8.1%); RSI > 75 +6.3% (so selling it is NOT a prediction, only profit-taking). `tests/advisor_rules_test.py` (17 checks, made-up histories).
- **WATCH tier and rule order** (advisor.py): ADD / BUYBACK need RSI < `rsi_buy`; WATCH = same test with RSI in [rsi_buy, rsi_buy + `WATCH_MARGIN` 10) (amount 0, score = closeness; closed positions capped at `WATCH_MAX_CLOSED` 8). Rule order for held assets: size cap TRIM, theme TRIM, RSI take-profit TRIM (value >= DUST and in profit), ADD (tiny positions too: a top-up beats CONSOLIDATE, which had been hiding oversold tiny positions), CONSOLIDATE (< 1 500 kr), REVIEW, WATCH. Pullback window now balanced 5-40% (the data showed no benefit from a tight cap once RSI + 200-day trend are required; conservative 10-25%, aggressive up to 60%). Theme cap still blocks ADD/WATCH in an over-weight sector (e.g. Technology 45%). TRIMWATCH (mirror of WATCH on the sell side): in profit, value >= DUST, RSI in [rsi_sell - 10, rsi_sell], amount 0, score = closeness; rule sits after WATCH. Trim panel order: TRIM, REVIEW, TRIMWATCH, CONSOLIDATE. Portfolio panel `Add / buy back / watch` lists signals first, then WATCH by nearest RSI; WATCH badge = dashed grey. Portfolio tables: Vol 3M column is placed directly before Day % (columns 1 logo, 2 name, 3 cur, 4 qty, 5 gav, 6 price, 7 vol, 8 day, 9 value, 10 return %, 11 return kr; responsive.css hides 5 below 900 px, 3/4/7/11 below 700 px, 1/6 below 520 px); `dayCell()` bolds Day % when |day / vol| >= 2.
- **HTTPS**: server.py wraps connections itself when `data/tls/cert.pem` + `key.pem` (or `--cert/--key`) exist: default mode with a certificate = plain http on `--port` PLUS https on `--https-port` (8443) in a second `DashboardServer` thread (so the LAN IP keeps working); `--https-only` = https on `--port` and plain `http://` gets a 301 to `https://`; handshake in the request thread (a stalled client cannot block the accept loop), the session cookie gets `Secure`, handshake noise is silenced. ## One source of truth (valuation.py)
RULE: no module prices anything itself. `valuation.snapshot(payload, quotes)` is the only place live prices meet the Nordnet export (live price used only when same currency as the export and 0.5x-2x of the export price, never `0P` funds; value = export value x live/export price; unrealised = value - (export value - export unrealised); day P&L = value - value/(1+day%); account = holdings + ledger cash; all-time = account - net deposits). `valuation.apply(payload, snap)` returns a copy of the analytics payload with every value-dependent field live (assets, overview, scorecard top_weight / fragmentation via `build_scorecard`, dividends share). server.py `_valued(uid)` = (applied payload, snapshot) is used by /api/trades (plus `deposit_behavior` rebuilt on real daily NAV via `trade_analytics.rebuild_deposit_behavior(ap, nav_by_day)`, `payload['_cash_events']` is private and popped), /api/assets, /api/snapshot, /api/advice (the advisor no longer prices: it uses `a['value']`; cache 60 s), /api/reports, /api/ask and /api/nav (`nav.anchored(curve, snap)` replaces the last day with the snapshot: account value, cash, category values; growth last step). The browser merges /api/snapshot (30 s) and never prices. Tolerance `valuation.allowed(x) = max(5 kr, 0.05% x)`; `python tests/consistency_test.py` (31 checks across all routes) must pass after any number-related change. Cost basis = Nordnet export (`Avkast. SEK`), NOT the ledger average cost: the two differ by about 1% and the ledger figure was the cause of a duplicate number before this change. Price history refresh is stale-while-revalidate (`nav._refresh_in_background`).

## Net asset value curve
`nav.py` -> `/api/nav` (user session). Per weekday from the first ledger day: shares from the ledger (`trades[].pos_after`, piecewise constant) x Yahoo RAW daily close (`period1`, not dividend-adjusted) x that day's FX (`{CCY}SEKX=X`-style symbols, pence units GBp/ILA/ZAc handled) + cash from `deposit_behavior.series`. Assets Yahoo cannot price (funds `0P`, no symbol) or whose symbol fails the TRUST CHECK (median of trade-price / Yahoo-price in SEK outside 0.6-1.7, e.g. the US `SMH` mapped to the euro-listed VanEck UCITS ETF, 6x too high) use their own trade prices (`gross/qty`) interpolated linearly and ending at the export price. Split fix: trade price / Yahoo close snapped to a clean factor (2, 3, 10, 1/2 ...) applied until the next trade. Growth = time-weighted: total `r = (NAV - deposits)/NAV_prev - 1` (includes dividends and fees); category growth = price return of yesterday's shares (buys/sells are not growth). Categories use the heat-map rule (`_category` mirrors `heatCategory()` in heatmap.js). Output: dates, total {nav, cash, net_deposits, twr}, categories {value, twr, first}, coverage (yahoo %, estimated names, symbol_rejected, split_fixed, NAV vs export on the export date: 0.8% off at 2026-11-06), summary per range (also given to the chat as `payload['nav']`, cached only). Price history shared in `nav_price_cache.json` (public, gitignored); curve cached per owner (10 min, max 6, `nav.forget(uid)` on file changes). Front end `nav.js`/`nav.css` in `#nav-section` above `#predictions-section`: range chips are single choice, categories are multi-select (max 8), chart is recreated only when the view changes (value <-> growth) so the privacy plugin state stays right. Where to check the logic: ALL the maths is in `nav.py` (`curve()`: shares per day, Yahoo price x FX, split snap `_snap`, trust check, cash, NAV, time-weighted `twr`, category index; `_summary()` for range stats); `nav.js` only slices the ranges, re-bases growth to 0 at the range start, draws, and recomputes the four tiles from the server arrays. Run `python tests/nav_math_test.py` for the synthetic logic check. Display: smoothing is drawing only (`smoothed()` in nav.js: triangular moving average, radius 2/5 capped at n/12, exact end points, monotone curve; tooltip `raw` arrays stay exact), NAV white / deposits gold dashed / green-red fill between them (`fill: {target, above, below}`), end labels plugin `navEnd`. Verified with a synthetic world (deposits are not growth, +10% on a 25% holding = +2.5% total, split and wrong-symbol cases) and in headless Chrome at 320-1280 px.

`start-dashboard.bat` (runs `nordnet_sync.py` ONCE to rebuild portfolio_baseline.json from the 2 newest exports, then the auto-restart server loop; the user drops ALL CSVs into the project folder by hand - no Downloads watching, no `--watch`), `stop-dashboard.bat`, `install-autostart.bat` / `uninstall-autostart.bat` (optional login start via the Startup folder). Server still listens on all interfaces on purpose (Tailscale).
